# Baviera Control

Plataforma de gestão de negócios da BMW Motorrad Aveiro (Caetano Baviera). Página única (`index.html`) servida pelo GitHub Pages, com dados no Supabase.

## Como está organizado

| Pasta | O quê |
|---|---|
| `index.html` | A plataforma. Ao mudar, atualizar **as duas** versões no topo: `<meta name="app-version">` e `const APP_VERSION`. |
| `sql/base/` | Esquema da base de dados tal como estava em produção (tabelas, regras, funções). Sem dados. |
| `sql/migracoes/` | Alterações à base de dados, por data. Correm-se à mão no SQL Editor do Supabase. |
| `sql/APLICADAS.txt` | Migrações já corridas em produção. As que não estão aqui são "pendentes". |
| `tests/` | Testes automáticos (ver abaixo). |
| `.github/workflows/testes.yml` | Corre os testes a cada alteração. |

## Testes

Correm sozinhos no GitHub (separador **Actions**) a cada alteração. Localmente: `cd tests && npm install && npx playwright install chromium && npm run todos`.

- **permissoes** — monta uma base de ensaio (Postgres 17 em memória com o esquema real, sem dados de clientes), aplica as migrações pendentes duas vezes e testa cada perfil (chefe, vendedor, secretário, assessor, financeiro, eventos externo, conta nova, anónimo) contra cada tabela.
- **csp** — a política de segurança da página bloqueia envios para sites estranhos e a biblioteca de Excel só carrega se não tiver sido adulterada.
- **xss** — enche todos os campos de texto com código malicioso e percorre todos os ecrãs de todos os perfis e todos os PDFs. Falha se algum campo entrar sem proteção.
- **erros** — erros do browser chegam à tabela `erros_cliente`, sem duplicados e com limite.
- **ecras** — o botão "Apagar" só aparece quando o servidor deixa apagar; conta nova vê a mensagem de espera.
- **encomendas** — lê um ficheiro fictício do portal BMW (CSV em Windows-1252 e Excel), recupera o código de modelo que o Excel estraga, confirma a ordem, que o vendedor só lê e que pesquisa e filtros funcionam. Também testa as três origens (Stock Aveiro, Rede e BMW: deteção pelo critério do portal, pelo nome ou pelos concessionários; cada uma gravada à parte; sem clientes de outros concessionários) e "estou a negociar": quem vê o quê, a escolha do negócio, os avisos no campo Encomenda e os alertas de reserva parada. Nunca pôr aqui um ficheiro real: tem apelidos de clientes.
- **comerciomargem** — Vendas › Comerciante com a margem de cada venda a comerciante (saída − entrada, menos oficina e legalização já gastas se a mota estiver no stock; sem garantia nem comissão), total no topo, quantas a perder dinheiro e sem valor de entrada; a entrada escreve-se na própria linha (grava no negócio) sem abrir o negócio; Usadas › Margem mostra as vendas a comerciante com a mesma conta e não muda nas vendas normais.
- **eotimg** — colar um print (Ctrl+V) num comentário de EOT: a imagem é reduzida, vai para o Storage privado na pasta do contrato e aparece no histórico carregada com a sessão (sem links públicos).
- **negimg** — colar um print (Ctrl+V) num comentário do negócio (ou arrastar, ou botão «Imagem»): a imagem é reduzida, vai para o Storage privado na pasta do negócio e aparece no histórico carregada com a sessão (sem links públicos); comentário só com imagem; as imagens por enviar ficam no seu negócio; sem permissão ou sem o SQL diz porquê e não grava; imagem em grande (tamanho real ao clicar, Esc fecha); «Comentários novos» mostra «enviou uma imagem»; telemóvel.
- **adenda** — EOTs com adenda contam como renovado; quando o mapa traz o mesmo contrato com data de fim nova, a importação mostra-o e volta a pô-lo em "Por contactar" (fica a data da adenda). Sem o SQL, avisa em vez de falhar.
- **importacao** — mapa novo das EOTs sem perder nada: diz quantos contratos já existiam (iguais / com dados novos do banco, antes → depois), campo vazio no ficheiro não apaga, correção feita à mão depois da última importação fica, contrato repetido no ficheiro fica com a linha de data de fim mais recente, o mesmo contrato com zero à esquerda junta-se ao que existe, o trabalho da equipa nunca vai no envio, os que saem não são apagados e há aviso quando quase todos saem (mapa antigo).
- **eotmanual** — EOTs criadas à mão pelo chefe (não vieram no mapa): formulário na página com nº, cliente e data de fim obrigatórios; o mesmo nº escrito de outra forma não cria outro (avisa e abre o que existe); números à portuguesa; marca «à mão» na lista, na ficha e no ecrã do vendedor; apagar só os criados à mão; a importação não os dá como saídos e, quando vêm no mapa, juntam-se e passam a ser do banco sem perder o trabalho da equipa. Sem o SQL novo, diz o que falta.
- **retomas** — Usadas › Retomas: registo dos valores de retoma que o chefe dá (vendedor que pediu — vendedores e o chefe —, matrícula, modelo, ano, km, extras, valor oferecido, preparação, venda prevista e mínima; registos antigos mostram o cliente que tinham); ao escrever a matrícula ou o modelo e ano mostra os valores já dados; os valores ficam fixos (só estado e notas mudam; outro valor = registo novo); margem simples na lista; filtro por estado; só o chefe. Sem o SQL, diz o que falta.
- **acordo** — botão «Acordo de venda» só nos negócios de motas usadas (MU), para o vendedor do negócio e o chefe: o PDF da empresa (docs/acordo-venda-usados.pdf) sai preenchido com o negócio (cliente, NIF, morada, CC, contactos, modelo, matrícula, valor de venda, retoma) e com o que se escreve no painel (data, cor, km e data da matrícula vindos do stock quando existem, empresa, marca da retoma, forma de pagamento, observações, BMW FS; o sinal e os dados da retoma vêm do negócio); grava sozinho; contas de sinal, retoma e valor a liquidar; o ficheiro chama-se «Acordo de venda <matrícula>.pdf»; as notas internas do negócio nunca vão para o PDF; diz o que falta no negócio; sem o SQL avisa e descarrega na mesma; telemóvel. Cada PDF descarregado fica guardado no negócio tal como saiu (bucket privado negocio-documentos + registo documentos_emitidos, com quem e quando) e aparece em «Emitidos» para abrir; sem esse SQL, avisa.
- **folha** — botão «Folha de Negócio» nos negócios de motas novas, demos e usadas (MN/MD/MU; nas usadas junto com o acordo), para o vendedor do negócio e o chefe: o modelo do chefe (docs/folha-negocio.pdf, gerado por docs/fontes/folha_negocio.py a partir do Excel dele) sai preenchido com o negócio — vendedor, Bizagi, cliente, morada + código postal, NIF, contacto, e-mail, matrícula e data, modelo, valor fatura (PVP), sinal, encomenda e retoma (modelo, matrícula, ano, km, valor ao cliente e do comércio, campos novos do negócio) — e com o painel (nº proposta, data, empresa, RGPD, Novo/Demo, origem, faturação, financiamento PP/F. Ext/F BMW/GAP/Proteção, subvenção, seguro, observações); por omissão vêm o tipo, a origem, o perfil e o financiamento do negócio; grava sozinho; ficheiro «Folha de Negócio <cliente>.pdf», guardado no negócio tal como saiu; o formulário do negócio grava sinal e retoma escritos à portuguesa como números; notas internas nunca entram; telemóvel.
- **desempenho** — Usadas › Desempenho e Melhorias, só do chefe: desde 1 jul (data editável, guardada no browser) separa as vendas a clientes em herdadas (já em stock antes do início, incluindo as vendidas antes de haver ficha no stock) e compras novas, com os dias até vender (as motas sem data de receção ficam fora das médias), a margem libertada real lançada nas Comissões por mês e por origem («por lançar» quando falta; nunca estimativas), o stock médio e o custo do stock parado (depreciação da Calculadora repartida pelos dias, com aviso das motas sem depreciação) e a antiguidade do stock no início e hoje; conta pela data de retail (como as comissões) ou do negócio e identifica as vendas negociadas antes do início; relatório para imprimir/guardar em PDF sem controlos, sem vendedor e sem as sugestões; Melhorias com as motas paradas pela regra dos 180 dias do chefe (preço mínimo, comerciante a 82,5 % e quantos meses parada isso equivale), compras abaixo da margem bruta de 1 500 € ao preço mínimo com a compra máxima, quanto custa o stock parado por mês e dados a corrigir; as margens são pedidas ao abrir; o vendedor não vê nem lê o stock completo; escuro e telemóvel.
- **eventosext** — eventos com perfil externo «Eventos» (pessoa de fora): entra direto num ecrã só com os eventos a que o chefe lhe deu acesso (continua depois de o evento acabar), vê as inscrições desses eventos — também as dos vendedores, só para ver e sem o funil — e regista convidados com a ficha completa (só altera os que registou) (nome completo, data de nascimento, NIF, telemóvel, camisola; pendura com os mesmos dados; mota que leva: própria, da Caetano ou outra, e modelo; estado e observações), com NIF validado; documentos (cartão de cidadão e carta de condução do cliente e do pendura, foto ou PDF até 10 MB) só depois de marcada a autorização escrita, guardados em privado na pasta evento/inscrição; Excel com tudo; o vendedor usa a mesma ficha (com funil e acompanhantes); o chefe dá e tira acessos por evento, dá o perfil Eventos a contas novas e muda quem registou cada inscrição; telemóvel.
- **comfixa** — Comissões: coluna «Comissão fixa» por negócio; o valor que o chefe escreve substitui a regra (percentagem, mínimo garantido ou demo), não aceita negativos e apagar volta à regra; o vendedor vê só o valor.
- **usodiario** — uso diário: pesquisa por telemóvel (com ou sem 351/espaços) e por matrícula sem hífenes, com a coluna «Telemóvel» nos resultados; botão de WhatsApp que só abre a conversa (wa.me, sem texto) no negócio, no Hoje do vendedor e nos EOT; Home do chefe com os números primeiro e uma única faixa «A tratar (N)» que abre ao toque; barra inferior Home · Vendas · Usadas · Funil · Mais e o grupo fechado «Menos usadas» (Leads, Escala, Exportar); formulário do negócio com o bloco «Essencial» sempre aberto (retoma, sinal e forma, NIF, e-mail, financiamento) e os restantes grupos fechados, também no registo novo; Ctrl+P leva à pesquisa; nenhuma letra abaixo de 11 px no ecrã; erros num aviso discreto em vez de janelas do browser, apagar com «Anular» durante 5 s e confirmação dentro da página só para o que não tem volta; nome «Bimby Motorrad» no menu, no ícone e no manifesto; vermelho só para o que está em atraso, âmbar para o que é para tratar. Como a Bimby deixou de usar `alert`/`confirm` do browser, os outros testes ligam `tests/_avisos.js` (`ligarAvisos`), que aceita ou recusa as perguntas da página, regista os avisos de erro e encurta o tempo do «Anular».
- **alertas** — declaração de circulação (mota nova vendida, 90 dias depois da matrícula; "Por atualizar" mantém o aviso, "Atualizada" tira-o) e aniversários dos clientes (um aviso por cliente; à segunda inclui o fim de semana; 29/02 a 28/02). Sem o SQL, os campos novos não aparecem e o negócio grava sem eles.
- **notificacoes** — notificações das EOTs: a última indicação espera pelo outro lado (vendedor/chefe → financeiros; financeiro → responsável e chefe se escreveu); «Lido» por pessoa; responder passa a notificação; o chefe vê as conversas penduradas; aviso do computador com a página em segundo plano.
- **financeiros** — visto «tratado» dos financeiros nas EOTs (como o seguro das demos): coluna ✓ para dar/tirar o visto sem abrir o contrato (e botão dentro do contrato); o servidor grava quem e quando; o visto cai sozinho quando o vendedor/chefe escreve depois dele ou o mapa reabre o contrato; submeter uma indicação não dá o visto («Em curso»). Coluna «Indicações» (✓ Tratado · 🔔 Pergunta/Resposta · ↻ Reaberto · Em curso · Novo · Por tratar) e separadores «Precisa de vocês / Já tratados / Todos». Sem o SQL do visto: aviso e regra antiga.
- **hoje** — ecrã «Hoje» do vendedor: registo rápido (nome, telemóvel, modelo, fase; Enter regista; lembrete pela fase); ações na linha «Para contactar hoje» sem abrir o negócio (Contactei, Adiar 1/2 semanas ou 1 mês, Perdido com motivo num toque; a mota do stock volta a Disponível; se o servidor recusar, a linha volta); ficha solta → «Guardar num negócio» (negócio novo em Quente ou juntar a um negócio em curso do funil/Carteira, mesmo nome primeiro; o chefe escolhe o vendedor). Menu do vendedor arrumado em Vender · Clientes · O meu mês: «Stock» com separadores (Novas BMW · Usadas e demos · Equipamento; abre no último usado), indicações dos financeiros dentro das EOTs (um só número), «Vendidos e perdidos» com separadores Retail/Perdidos; barra de baixo do telemóvel igual. Frase-resumo no topo do Hoje (clientes para contactar, EOTs à espera, entregas da semana); no painel do chefe, Retail do mês contra o mês anterior até ao mesmo dia, em motas.
- **reuniao** — separador «Reunião semanal» do chefe (terças às 15:00, 20 minutos; relógio do teste parado numa terça às 14:30): números de cada ponto desde a reunião anterior (compromissos cumpridos e fora do prazo, Retail contra o objetivo e o mês anterior, ritmo, margem do último mês lançado só nesta vista, entregas a 2 semanas e o que falta, EOTs a 90 dias e indicações por ler, novas livres e ST→US, usadas por antiguidade com o preço alterado ali mesmo, equipamento da semana e stock morto/moribundo, eventos), perguntas para fazer, compromissos (registar com Enter, marcar feito, apagar, nova data; volta atrás se o servidor recusar; por cumprir conta até ao dia da reunião; repetidos assinalados «Repetido · 2.ª vez» quando voltam a ficar por cumprir depois de uma nova data ou há mais de uma semana, com pergunta própria), condução ponto a ponto com relógio total e do ponto, resumo para a equipa sem margens, terminar/retomar guardado no computador, aviso antes do SQL, telemóvel e acessibilidade claro/escuro.
- **stus** — lembrete ao chefe: motas ST de Aveiro com 90+ dias no stand (desde 193) para pedir a mudança para US; Home e A tratar, "→ US" na tabela, "Já pedi" esconde até ao próximo ficheiro.
- **equip** — Stock Equipamento: referência com ou sem espaços; aviso quando está noutra loja; referência fora do mapa procurada no site (e a venda fora do stock já vem preenchida); filtros de antiguidade e desconto mínimo; ordenar por mais tempo sem vender.
- **acessibilidade** — axe-core (WCAG 2.2 AA) em 65 ecrãs dos 6 perfis, computador e telemóvel, claro e escuro, mais medição à mão do contraste que o axe não decide (números pequenos, placeholders). Falha com qualquer violação.
- **fichas** — várias fichas de margem no mesmo negócio (uma por mota): cada uma grava na sua linha, troca sem misturar dados, marcar a vendida arquiva as outras, alerta enquanto não se escolhe; e aprovação quando o esforço passa a margem variável.
- **recusar** — o chefe aprova ou não aprova cada ficha: «Não aprovar» abre o motivo na própria linha (sugestões de um toque; sem motivo não grava; Enter confirma, Escape fecha); a ficha passa para «Não aprovadas, à espera do vendedor», o vendedor vê o motivo nos comentários do negócio, na ficha e no PDF; quando muda a ficha, volta ao chefe; «Aprovar mesmo assim» limpa a recusa. Sem o SQL novo, a lista continua e o aviso diz o que falta.
- **integridade** — escreve números à portuguesa a velocidades aleatórias, com rede lenta e falhas, e confirma que o gravado é igual ao escrito.

## Ao mudar a base de dados

1. Criar `sql/migracoes/AAAA-MM-DD_nome.sql` (tem de poder correr duas vezes sem erro).
2. Enviar para o GitHub: os testes correm a migração na base de ensaio.
3. Se passar, correr no SQL Editor do Supabase e acrescentar o nome a `sql/APLICADAS.txt`.
4. De vez em quando, voltar a ler o esquema de produção para `sql/base/` (garante que a base de ensaio não se afasta da real).

## Cópias de segurança

O plano gratuito do Supabase não guarda cópias. **As imagens das EOTs (Storage) não entram nesta cópia**: só a base de dados. A rotina `copia-seguranca.yml` faz uma por noite, cifrada com a frase-senha `COPIA_SENHA`, e repõe-na logo numa base vazia para confirmar que serve (contagem tabela a tabela). As cópias ficam 30 dias em **Actions → Cópia de segurança → execução → Artifacts**.

Abrir uma cópia à mão (precisa de GnuPG; no Windows, Gpg4win): `gpg -d copia-AAAA-MM-DD.tar.gz.gpg | tar xzf -`. Repor no Supabase: correr `pg_restore` com a ligação do projeto — pedir ajuda antes de o fazer.

O GitHub desliga rotinas agendadas em repositórios públicos sem alterações durante 60 dias: se isso acontecer, aparece um aviso no separador Actions e basta reativar.
